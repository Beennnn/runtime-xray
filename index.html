Runtime X-Ray

Voir ce qu'une exécution Java a réellement fait.

  • 1Il s'intègre à une exécution Sans toucher au code ni au build : les observateurs sont injectés au démarrage de la JVM, quelle que soit la façon dont elle est lancée.
  • 2Trois outils observent JaCoCo relève les lignes exécutées, async-profiler mesure le temps, Arthas capte les valeurs reçues. Chacun produit son rapport, dans son format.
  • 3Leurs sorties sont réunies Les trois rapports sont agrégés dans une seule vue : une page à lire plutôt que trois formats à rapprocher soi-même.

Ce qui suit vient d'une exécution réelle : un calculateur de temps de trajet (22 classes, 8 paquets), sous Java 21. Toutes les pages ci-dessous sont des sorties d'outils, pas des captures d'écran.

La vue agrégée

C'est le livrable : les trois observations réunies, navigables ensemble.

Une exécution COMMENCER ICI
À gauche, tout le code qui a tourné, du plus coûteux au moins coûteux. Un clic ouvre la méthode : lignes exécutées en vert, jamais atteintes en rouge, les appels qui partent de chaque ligne avec leur durée — et en bas les valeurs reçues, appel par appel. Les noms de méthodes du code sont cliquables : on suit l'appel sans quitter le source.
Trois exécutions comparées MULTI-RUN
Le même outil lancé trois fois, avec des jeux de données différents. Un sélecteur passe de l'une à l'autre, l'arbre d'appel prend les exécutions pour racines, et la liste signale ce qui n'a tourné que dans l'une d'elles.

Les sorties brutes de chaque outil

Ce que la vue agrège, dans le format natif de chaque outil. JaCoCo  ·  async-profiler  ·  Arthas

Couverture, vue nettoyée
Le même rapport que ci-contre, restreint aux classes réellement exécutées : le code jamais atteint est retiré, on ne navigue que dans ce qui a servi.
Couverture complète
Tout le code, exécuté ou non. Source annotée ligne à ligne : vert exécuté, rouge jamais atteint, jaune branche partiellement couverte.
Arbre d'appel
Qui appelle qui, dépliable et cherchable, avec la part de temps de chaque branche. Le bouton « Expand All » ouvre tout d'un coup.
Flame graph
La largeur d'une barre est le temps passé dessous. Cliquer zoome sur une branche, taper cherche une méthode.
Valeurs des paramètres
Les valeurs réellement reçues, appel par appel : @Mode[CAR] @Weather[SUNNY], et ce que la méthode a renvoyé. C'est précisément ce que ni la couverture ni le profil ne savent donner.
L'arbre d'UN appel
Le chemin réellement emprunté par une seule invocation, avec les numéros de ligne — de quoi retourner droit dans le source. Là où le profil, lui, agrège.
Aucun de ces trois outils ne répond seul. La couverture ignore le temps et les valeurs ; le profil échantillonne, donc il ne prouve jamais qu'un code n'a pas tourné ; l'inspection des valeurs ne regarde qu'une méthode désignée. C'est leur combinaison qui répond — et c'est ce que la vue agrégée assemble.

Le lancer sur votre projet

Mode d'emploi ↗
Un seul fichier, lancé par le java déjà présent : aucune contrainte sur la façon de démarrer l'application, aucune licence, et aucune connexion pendant l'exécution. Paramètres, fichier de configuration, publication du résultat.
Le dépôt ↗
Le code de l'outil, l'application de démonstration, et l'évaluation des dix-huit outils comparés avant d'aboutir à cette combinaison.
Produit par JaCoCo, async-profiler et Arthas — libres, gratuits, et fonctionnant sans connexion.
En marge : Java 21 contre Java 25, mesuré sur le même programme — spectaculaire, mais sans effet sur la solution retenue.
